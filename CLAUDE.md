## Project

A blog backend service built with [Hono](https://hono.dev/) (web framework), [Drizzle ORM](https://orm.drizzle.team/) (Postgres), and [better-auth](https://www.better-auth.com/) (authentication), running on Bun.

## Commands

- Install dependencies: `bun install`
- Run dev server (hot reload): `bun run dev` — serves at http://localhost:3000
- Generate a migration from schema changes: `bunx drizzle-kit generate`
- Apply migrations to the database: `bunx drizzle-kit migrate`
- Push schema directly to the database (no migration file): `bunx drizzle-kit push`
- Browse the database: `bunx drizzle-kit studio`

There are no lint, build, or test scripts configured in `package.json` yet.

Requires a `.env` file with `DATABASE_URL`, `BETTER_AUTH_SECRET`, and `BETTER_AUTH_URL`.

## Branching

See [CONTRIBUTING.md](./CONTRIBUTING.md) for the branching strategy: `master` → `release` → `uat` → `production`, with `uat`/`production` merges requiring the repo owner's approval.

## Architecture

Layered structure per resource (`blog`, `user`), each following controller → service → repository:

- `src/controller/*.controller.ts` — Hono request handlers, checking required fields and calling the corresponding service.
- `src/service/*.service.ts` — business logic between controllers and repositories.
- `src/repository/*.repository.ts` — Drizzle queries against the DB, exported as an object of methods (e.g. `userRepository.findById`, `.findByEmail`, `.deleteById`).
- `src/ts/*.ts` — shared types/enums per resource (`TUser`, `TBlog`, `EGender`), used to type repository/service params instead of inferring from the Drizzle schema directly.
- `src/db/schema.ts` — Drizzle table definitions: `blog` (app-owned), and `user`/`session`/`account`/`verification` (owned by better-auth — see below). `blog.userId` references `user.id`.
- `src/db/index.ts` — creates and exports the shared `db` (drizzle/node-postgres) instance. Both `src/utils/auth.ts` and the repositories import `db` from here (not from `src/index.ts`) to avoid a circular import now that `src/index.ts` itself imports `auth`.
- `src/middleware/auth.ts` — `requireAuth`, a Hono middleware that rejects requests without a valid better-auth session and sets `user`/`session` on the context.
- `src/utils/auth.ts` — configures the `better-auth` instance: `drizzleAdapter` (pointed explicitly at the `user`/`session`/`account`/`verification` exports from `db/schema.ts` — required, since drizzle-orm v1-rc dropped the `schema` option on `drizzle()` itself, so the adapter can't fall back to introspecting `db`), `emailAndPassword`, and `user.additionalFields.gender` for the app-specific field.
- `src/index.ts` — creates the Hono `app`, mounts better-auth's own handler at `/api/auth/*` (sign-up/sign-in/session endpoints — see below), mounts `router`, defines a placeholder `/` route.
- `src/router.ts` — intended to hold route definitions wiring controllers to paths; currently an empty Hono instance, mounted onto `app` but with no routes registered yet.

**Note on current state:** this is an early scaffold. Most controllers, services, `blog.repository.ts`, and `router.ts` are empty stubs — method signatures/shape exist but bodies are unimplemented. When implementing a new endpoint, follow the existing controller/service/repository method-name pattern (`create`, `findAll`, `findById`, `update`, `delete`) for consistency with what's already stubbed out.

**Auth is handled by better-auth, not hand-rolled.** Sign-up/sign-in are *not* implemented in `user.controller.ts`/`user.service.ts` — better-auth's own handler, mounted at `/api/auth/*`, serves `POST /api/auth/sign-up/email` and `POST /api/auth/sign-in/email` directly (body: `{ email, password, name, gender }` / `{ email, password }`). Credentials are stored by better-auth in the `account` table (`password` column there), never on `user` — `user.id` is a string generated by better-auth itself (not a DB identity column), which is why `blog.userId` and `user.id` are both `text`, not `integer`. `userRepository.create` still exists but is only for direct/manual `user` row inserts (e.g. seeding); it does not create a matching `account`/credential row, so a user created that way can't sign in via better-auth until one exists. Protect a route with the `requireAuth` middleware from `src/middleware/auth.ts`.
